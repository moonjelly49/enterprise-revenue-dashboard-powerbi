# Enterprise Revenue & Profitability Dashboard (Power BI)

Centralized BI solution for multi-channel revenue monitoring, margin analysis, target-variance tracking and churn-risk detection.

> **Honesty note:** A `.pbix` file can only be authored in Power BI Desktop (Windows), so it is not included. Everything needed to build it in ~2-3 hours is here: data, Power Query, DAX, theme, layout spec. The dataset is **synthetic** (seeded generator), with deliberately planted patterns: heavy-discount customers (low margin), churned customers, a weak Distributors channel.

## 1. Folder structure
```
data/          6 CSVs (4 dimensions, 2 facts)   ~19.4k sales rows, 2023-01 to 2026-09
scripts/       generate_data.py  (regenerate / resize the data)
powerquery/    queries.m         (M code for loading + cleaning)
dax/           measures.dax      (date table + ~45 measures)
theme/         executive_theme.json
```

## 2. Datasets and sources
| File | Grain | Key columns |
|---|---|---|
| fact_sales | one order line | OrderID, OrderDate, CustomerID, ProductID, ChannelID, RegionID, Quantity, UnitPrice, DiscountPct, NetRevenue, COGS |
| fact_target | month x region x channel | TargetMonth, RegionID, ChannelID, RevenueTarget |
| dim_customer | customer | CustomerID, Name, Segment, RegionID, SignupDate |
| dim_product | product | ProductID, Category, ListPrice, CostRatio |
| dim_region | country | RegionID, Region, Country, Territory |
| dim_channel | channel | ChannelID, Channel, ChannelType |

**Source:** generated by `scripts/generate_data.py` (Python standard library only; seed 42).
**To use real data instead**, public datasets that fit this model: Microsoft *Contoso Retail DW* sample, Microsoft *AdventureWorks* sample, and Kaggle's *Superstore Sales* dataset. Search for them by name, since I could not verify current download links from here. Map their columns to the tables above; you will need to derive COGS and targets yourself.

## 3. Step-by-step build

**Step 1: Load data.** Home > Get data > Text/CSV, or use `powerquery/queries.m`. Create a Text parameter `DataPath` (e.g. `C:\PBI\data\`) so the project is portable. *Why:* a parameter means one edit repoints every query.

**Step 2: Clean and type.** The M code sets data types, removes null revenue/date rows and de-duplicates OrderID. *Why:* wrong types (text dates) silently break time intelligence.

**Step 3: Model (star schema).** Model view, create these relationships, all one-to-many, single direction, from dimension to fact:
- dim_customer[CustomerID] -> fact_sales[CustomerID]
- dim_product[ProductID] -> fact_sales[ProductID]
- dim_channel[ChannelID] -> fact_sales[ChannelID]
- dim_region[RegionID] -> fact_sales[RegionID]
- dim_region[RegionID] -> fact_target[RegionID]
- dim_channel[ChannelID] -> fact_target[ChannelID]
- dim_date[Date] -> fact_sales[OrderDate]
- dim_date[Date] -> fact_target[TargetMonth]

*Why:* targets and sales share the Region, Channel and Date dimensions, so one slicer filters both and variance is computed correctly. Note targets sit on the 1st of each month, so analyse target variance at **month level or above** (day-level visuals will show targets only on the 1st). Also hide the foreign-key columns in the fact tables.
Optionally, add `dim_customer[RegionID]` to dim_region as an inactive relationship, to avoid an ambiguous path: sales region is taken from fact_sales[RegionID].

**Step 4: Date table.** Paste the `dim_date` DAX from `measures.dax`, mark it as the date table, sort Month by MonthNo. *Why:* SAMEPERIODLASTYEAR/TOTALYTD require a contiguous marked date table.

**Step 5: Measures.** Create an empty table `_Measures` (Enter data) and paste measure groups 01-06 from `measures.dax`. Set formats: % measures to 0.0%, currency to your symbol. What each group does:
- **Core:** Revenue, COGS, Gross Profit, **Gross Profit Margin % = GP / Revenue**.
- **YoY:** compares with the same period last year (works at day, month, quarter and year level); includes margin change in percentage points, YTD and rolling 3M.
- **Target variance:** Variance = Actual - Target; Attainment % and a traffic-light status and colour (use in conditional formatting > Field value).
- **Low margin:** flags customers under a threshold (30% default; make it a What-If parameter for a slider) and quantifies discount leakage.
- **Channel:** revenue share and rank.
- **Churn:** days since last purchase measured against the latest date in the data, then tiers: Healthy <= 45, Watch 46-90, High Risk 91-180, Churned > 180 days. Also revenue at risk (trailing 12 months).

**Step 6: Apply theme.** View > Themes > Browse for themes > `executive_theme.json`.

**Step 7: Build the pages.**

*Page 1, Executive Overview*
- KPI cards: Total Revenue, Gross Profit, GP Margin %, Revenue YoY %, Target Attainment %
- Line chart: Revenue vs Revenue PY by month (dim_date[Month])
- Clustered column: Revenue Target vs Total Revenue by Region
- Slicers: Year, Region, Segment

*Page 2, Margin & Low-Margin Accounts*
- Scatter: X = Revenue, Y = GP Margin %, details = CustomerName, size = Orders. The low-margin discounters appear bottom-right
- Table: Customer, Revenue, GP Margin %, Avg Discount %, filtered where Low Margin Flag = 1
- Bar: GP Margin % by Product Category; card: Margin Leakage from Discounts

*Page 3, Channel Performance*
- Donut/bar of Revenue Share % by channel; matrix Channel x Region with GP Margin % (conditional colour scale)
- Line: monthly Revenue by ChannelType. Expect Distributors to show the lowest margin

*Page 4, Target Variance*
- Matrix: Region rows, Month columns, values Variance %; conditional formatting by Target Status Color
- Waterfall or bar of Variance to Target by Region

*Page 5, Churn Risk*
- Cards: At-Risk Customers, Churn Rate %, Revenue at Risk
- Table: Customer, Segment, Last Purchase Date, Days Since Last Purchase, Churn Risk Tier, trailing revenue (sort by days descending)
- Stacked bar: customers by tier and Segment

**Step 8: Interactivity.** Sync the Year/Region slicers across pages (View > Sync slicers); add drill-through from Region to a customer detail page; add bookmarks for "Show low-margin only"; set tooltip pages for the KPI cards.

**Step 9: Validate.** Cross-check in Python: totals should match `fact_sales.csv` sums. Reference values from the generated data: GP margin about 39.5% (2023), 39.7% (2024), 40.9% (2025), 39.8% (2026 YTD); channel margins: Online Store 42.8%, Marketplace 41.0%, Direct 40.1%, Retail 38.5%, Distributors 36.3%.

**Step 10: Publish.** Home > Publish to Power BI Service. Set scheduled refresh if the source is a gateway-accessible folder or database. Optional: row-level security by Region (Modeling > Manage roles: `dim_region[Territory] = "EMEA"`).

## 4. Expected insights
1. Distributors have the lowest gross margin because of the highest discounts.
2. About 12% of customers carry an extra ~16pp discount, which pulls their margin below 30%.
3. About 15% of customers stop buying, which produces the High Risk / Churned list and the revenue at risk.
4. Regional targets are missed where churned accounts concentrate.
